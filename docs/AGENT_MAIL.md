# 招聘邮箱接入

BoLe 通过腾讯官方 Agent Mail CLI 导入投递简历，并在 HR 选定候选人、批准具体邮件后发送联系邮件。官方安装说明：https://agent.qq.com/doc/cli-setup.md 。

## 安装与授权

项目依赖已包含 `@tencent-qqmail/agently-cli`。其他机器先运行 `pnpm install`，再运行：

```powershell
pnpm exec agently-cli auth login
pnpm exec agently-cli +me
```

CLI 按 workspace 隔离授权。BoLe 子进程固定使用 `BOLE_MAIL_WORKSPACE`，未设置时沿用显式的 `AGENTLY_WORKSPACE`，两者都未设置时默认 `codex`，以复用首次在 Codex 中完成的授权。普通 PowerShell 中手工授权时先设置 `$env:AGENTLY_WORKSPACE = 'codex'`，再运行上述登录命令；否则 CLI 可能把凭据存到 `default`，导致服务找不到已有授权。只更换终端或重启服务不应要求重复授权。

在 CLI 提供的浏览器链接中完成授权。凭据由官方 CLI 管理，BoLe 不复制 OAuth token、不把 token 写入模型上下文。服务须以完成授权的同一操作系统用户启动。仅安装全局 CLI 或 Codex 邮件技能，不会自行赋予 BoLe 收取简历的能力；本项目的原生接入负责整个招聘流程。

## HR 操作

1. 候选人把简历作为普通附件发送到已授权的招聘邮箱。
2. 在 BoLe 新建任务中勾选「从招聘邮箱收取简历」，可点「检查邮箱连接」查看地址。
3. 输入岗位要求，如「招聘全栈工程师，熟悉 React、Node.js 和 PostgreSQL，有独立上线项目的经验」。邮件关键词是主题/正文检索条件，可留空；它不是附件全文搜索。岗位匹配由后续评估完成。
4. 可限定起始日期、最多检查邮件数（默认 50，最大 200）；日期按浏览器本地零点转换。点击开始，系统完成画像、邮箱导入、解析、评估、核查与报告。也可同时上传本地简历。
5. 报告完成后，HR 在对话中明确选择人选并提出联系需求，例如「我选 R01，请发邮件邀请线上面试，问他下周二下午是否方便」。Agent 准备纯文本邮件并展示审批卡。
6. HR 核对候选人、来源邮箱、收件地址、主题和完整正文，点批准后发送；拒绝不发送。修改内容时重新描述并生成新审批。

收件地址固定取该候选人投递邮件的发件地址，不从简历或模型输出中猜测，也不采用邮件中的 Reply-To 或指令。中介/代投邮件可能不是候选人本人，必须在审批时核对。当前邮件工具每次联系一个候选人，不支持批量群发、抄送或邮件附件。

## 执行与恢复

- 邮箱读取发生在持久化工作流的接入节点，源条件随工作流保存。普通附件进入既有 `saveUpload → runFetcher` 链路，不增加另一套评分逻辑。
- 来源表保存 job、上传 ID、message ID、attachment ID、投递发件地址和招聘邮箱。恢复时复用已导入附件及已接入简历；相同邮件附件不重复下载，同 job 仍使用原去重机制。
- 分页保留全部搜索条件；不自动翻查收件箱之外的目录。邮件读取是否会影响已读状态由官方服务决定；BoLe 不主动执行标记或删除命令。
- 单个附件最大 25MB，文件格式沿用上传支持范围，扫描 PDF、旧 `.doc` 等仍受原解析限制。超大附件下载链接、正文简历、压缩包及邮件中的 URL 不自动抓取。附件失败/跳过记录进入事件轨迹。
- CLI 调用在当前 BoLe 进程内串行，间隔至少 6.5 秒，以适配当前账号的每分钟 10 次限制；批量导入可能耗时数分钟。不同服务进程不共享这个限速器，账号限额仍以 `+me` 为准。网络、授权或限频失败会显示错误，不会伪造成功。
- 所有模式下，发信都创建独立的持久化 `recruitment-mail` 审批。服务只从批准记录读取固定参数，并原子认领一次，然后调用 CLI 的 `--confirmed`，不会让 Agent 自行确认。
- 发信前核对当前招聘邮箱是否仍与来源一致。失败或进程中断不自动重发；结果不确定时先查已发送邮箱，再决定是否重新准备邮件，避免重复联系。
- 招聘工作流版本升至 `1.4.0`；旧工作流受原有版本/实现校验保护，不静默迁移。本次场景请新建任务。

## API

`GET /api/mail/status` 返回已授权邮箱，或可读错误。

创建任务：

```json
{
  "requirements": "招聘全栈工程师，熟悉 React 和 Node.js",
  "uploadIds": [],
  "mailbox": {
    "query": "全栈",
    "after": "2026-11-01T00:00:00+08:00",
    "maxMessages": 50
  }
}
```

发送前的审批复用 `POST /api/run/:jobId/approvals/:id`，正文为 `{"decision":"approve"}` 或 `{"decision":"reject"}`；接口不接受替换收件人或正文。该操作不触发筛选工作流续跑。现有单机单用户、无独立登录鉴权的部署边界保持不变。

## 验证范围

`tests/integration/mail.test.ts` 使用命令与模型测试替身，验证分页过滤、附件导入与路径限制、原筛选流程、对话生成待审邮件、默认模式审批、精确收件人、重复发送拦截与账号切换保护。测试不会给真实候选人发信。真实账号完成授权并验证了邮箱身份及空收件箱搜索；真实简历质量和实际投递效果应通过后续场景验证。
