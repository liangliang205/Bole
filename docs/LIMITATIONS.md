# 已知限制与边界

> 这份文档只列**当前真实限制**。已移除的 mock/黄金集/HTML 报告不再作为"限制"出现。

## 1. 简历接入

| 项 | 当前行为 | 边界 |
|---|---|---|
| 来源 | 仅用户上传（API/UI/CLI `--files`） | 不做 IMAP/Exchange 邮箱拉取；没有 mock 邮箱 |
| 格式 | PDF（文本层）、DOCX、TXT、MD、HTML、PNG/JPG/WebP/BMP/TIFF | 旧版 `.doc` 明确拒绝，提示另存 docx |
| PDF 扫描件 | 文本层为空时直接报错，提示上传图片 | 未做 PDF 页面渲染后 OCR（需要 canvas；P1） |
| 图片 OCR | 本地 Tesseract `chi_sim+eng`，或 `BOLE_OCR_URL` 外部服务 | 手写体、低分辨率、复杂版式准确率有限；OCR 文本会进入后续解析，错误会向下游传播 |
| 语言数据 | `pnpm ocr:download` 下载到 `data/ocr`，已 gitignore | 未下载时图片简历失败并给出提示；Docker 镜像构建时下载 |
| 单文件大小 | ≤25MB | 大文件 base64 传输会占用内存 |
| 附件数量 | 支持多文件上传 | 每份文件独立成一份简历；不做一封邮件多附件聚合 |
| 去重 | 同 job 内 sha256 + 身份指纹（姓名/手机/邮箱归一化） | 跨岗位重复投递不抑制；身份缺失时退化为正文指纹，可能漏判 |

## 2. 模型与质量

- **真实 API 必需**：没有已绑定的 DeepSeek Key 时 `bootstrap` 立即失败；产品路径没有 mock 回退。Key 不从环境变量读取。
- **模型非确定性**：温度=0 仍可能有 ±1 分波动；同一批简历重跑 Top5 可能变化。
- **流式 structured 输出**：token 先进入前端"实时生成"，最终仍以完整 JSON 的 schema 校验 + 两阶段提交为准；无效输出会重试，前端可能看到一段被丢弃的 token。
- **流式 usage**：DeepSeek 通常返回最终 usage；若网关不返回，成本按 `estimateTokens` 估算，不是账单精确值。
- **质量未做真实 A/B**：flash/pro 的分层是工程策略（扇出用 flash、判断/否决用 pro），没有"分档一定更好"的量化结论；需真实 Key + 人工标注重复实验。
- **未接入 LLM-as-judge**：没有五维 LLM 评分、P/R/F1、NDCG、kappa。

## 3. 编排与恢复

- 容量池满时**直接拒绝 + 退避重试**，不维护全局队列；高并发下可能看到多次 admission 退避。
- 批流动避免全局 barrier，但单批内仍按解析→初筛→深评→核查顺序推进。
- 检查点续跑覆盖批次与任务级；不做 SQLite 事务级崩溃一致性保证。
- HITL 在 Web 中只保存在当前服务进程内存；服务重启后，运行中的 HITL 问题会丢失，需要从检查点续跑重新触发。
- 运行中的 SSE 连接不跨进程恢复；刷新页面会重新连接当前 job（如果服务仍在运行）。

## 4. 前端与部署

- 单机单用户设计；默认只监听 `127.0.0.1`，没有登录、权限、多租户。
- Key 由服务端 AES-256-GCM 加密持久化在 `data/keyring.*`；同一数据目录下的所有浏览器共享该绑定。主密钥与密文在同一文件系统，属于本机文件保护级别，不是 HSM/KMS；生产应换用密钥管理服务。
- 没有浏览器级 e2e 测试；UI 通过静态检查、HTTP 冒烟与手工使用验证。
- 报告只有 Markdown + JSON（+ 成本报表/收敛 SVG），**没有 HTML 报告**。
- 成本页的 token 统计来自台账 `llm_calls`；流式估算与真实账单可能有差异。
- Docker 构建需要在构建期访问 tessdata 下载 OCR 数据；离线构建需预置 `data/ocr` 并调整 Dockerfile。

## 5. 合规与公平

- 公平性规则基于关键词/正则识别受保护属性并从 JD 中剥离；不能覆盖所有隐晦表达。
- 报告与日志做 PII 掩码；台账保存哈希与路径，不保存明文手机号/邮箱；但运行目录中的原始简历仍是明文，需要靠文件系统权限保护。
- 平台只给建议，不自动拒绝候选人；最终决定必须由 HR 做出并留痕。

## 6. 后续优先级

| 优先级 | 事项 | 原因 |
|---|---|---|
| P1 | 扫描版 PDF 页面渲染 + OCR | 真实简历中扫描件比例高 |
| P1 | 真实模型质量评测（人工标注 + 重复实验） | 当前只有机制验证 |
| P1 | Web 鉴权与多用户隔离 | 公网/团队使用前提 |
| P1 | 浏览器级 e2e（上传→HITL→报告→证据） | 防止 UI 回归 |
| P2 | 邮箱 IMAP/Exchange 接入 | 减少手工上传 |
| P2 | OCR 版面分析（表格/分栏） | 提升图片简历字段准确率 |
