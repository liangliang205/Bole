# 岗位约束与证据校准

项目内 Agent skill：`config/skills/evidence-calibration.md`，当前版本 `1.0.0`。这是招聘推理规则，不是 Codex 工具技能，不需要安装外部插件。

## 如何生效

`src/agents/prompts.ts` 将该技能作为平台补充规则接入 profiler、parser、assessor、auditor。即使活动 Agent 仍使用旧模板，也会收到这些约束；不会修改数据库内已有 Agent 定义或已提交评分。

新招聘工作流为 `1.2.0`；技能内容及其处理代码参与工作流实现指纹。调整技能和执行语义后应发布新的工作流版本，不能让旧运行悄悄换规则。技能维护者应保留旧版可执行代码，历史会话不会自动重新提取或改分。重启服务后，新建会话并重新上传材料，以验证新流程。

## 哪些由代码保证

- 画像生成的评分卡若给“经验不限/应届生可”岗位增加工作年限或雇佣经历维度，会触发校验重试。
- 明确“后端不做要求”却生成后端能力评分维度时，触发校验重试。
- 应届岗位锚点擅自添加未要求的 Kubernetes、多云、大型架构或团队技术领导力，会触发校验重试。规则使用有限的文本模式，不是完整语义理解。
- 解析保留空字段，不把可选工作经历、年限和薪资缺失自动归为质量异常；仍保留真正的时间线冲突或提取问题。
- 原文包含明确云平台项目环境和部署实践时，拦截“仅了解云部署”等明显矛盾的概括。它不证明候选人独立承担了所有部署工作。
- 核查必须逐维度覆盖，不能只给一个“整体通过”。

上述校验失败会同轮重试，持续失败则显式失败；不会通过代码强行提高某个人的分数。权重和最终分数仍由冻结评分卡与既有总分公式计算。

## 哪些依然需要模型判断

对个人职责、证据支持程度、React/Next.js 实践深度、项目交付和学习能力的判断仍由 LLM 完成。要求它汇总技能段、项目环境、技术栈、架构与成果；区分明确反证、未提及、范围待确认。重评可以补证或收窄措辞，不默认把每次核查当作降分指令。

对于“需要实际云部署经验”，项目明确列出云服务器、容器化与上线成果是支持证据；个人部署步骤、负责范围、域名/HTTPS 或故障处理细节可以追问。只有岗位明确要求生产运维、CI/CD 或多云时，才能把它们作为对应门槛。

本技能没有把某份简历设为必推样本，也未改推荐分数阈值。3/5 折算为 60 分，与既有 72 分推荐阈值的含义应明确区分；若业务要改变阈值，需通过独立的评分标准版本确认，不应暗中改分。

## PDF 与证据展示

有文本层的 PDF 仍使用 PDF.js，不自动调用本地 OCR。现在根据文字坐标恢复行序，并按文字片段间距拼接；没有可用坐标或旋转文本时回退原始内容顺序。复杂分栏、跨行表格等仍需核对原文件，不能承诺通用版面还原。

证据偏移对应当前版本提取的规范化文本，不是 PDF 字节位置。提取算法改变后必须重新生成引用，旧引用保持其旧文本坐标，不自动迁移。

候选人面板按中文字段名和阅读顺序显示，长字段分行，原文引用默认折叠；空字段单独收纳。“提取置信度”是解析模型对字段提取的估计，不代表招聘推荐置信度或外部事实认证。

## 验证

`tests/unit/evidence-policy.test.ts` 覆盖岗位约束、缺失字段、云部署反证、核查维度覆盖、PDF 行序/断字及实际技能接入。`pnpm check` 运行完整回归；模型协议测试使用测试替身，不能据此声称真实模型质量已经得到基准验证。
