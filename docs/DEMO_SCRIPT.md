# 演示脚本（真实数据 · 对话式控制台）

> 目标：在 8–10 分钟内展示"上传真实简历 → 多 Agent 编排 → 流式生成 → HITL → 证据链 → 报告"的完整闭环。
> 前提：启动 Web 后已按弹窗绑定 DeepSeek Key（服务端持久化），已执行 `pnpm ocr:download`（若演示图片简历）。

## 0. 准备

```bash
pnpm install
pnpm ocr:download
pnpm bole reset --yes    # 从空台账开始，避免旧会话干扰
pnpm web
# 首次进入按弹窗绑定 DeepSeek Key；绑定一次后持久化
```

准备 5–8 份真实/脱敏简历，至少包含：
- 1 份 PDF（文本层）
- 1 份 DOCX
- 1 张图片（JPG/PNG）
- 2 份同岗位但质量差异明显的简历
- 可选：1 份重复文件，用于展示去重

招聘需求示例：

> 急招 Java 后端工程师，3–5 年经验，熟悉 Spring Boot、MySQL、Redis，有微服务与高并发经验，base 上海。团队做支付交易链路，希望有稳定性治理经验。

## 1. 新建会话（0:00–1:00）

1. 点击「＋ 新建筛选会话」。
2. 粘贴招聘需求。
3. 点击「＋ 上传简历」，多选全部文件；观察 chips 从"上传中"变为大小。
4. 点「开始筛选」。

讲解点：
- 文件先落 `data/uploads/<uploadId>/`，运行时由探马读取；不是把文件内容塞进 prompt。
- 页面所有操作都走 `/api/*`，没有 CLI 隐藏步骤。

## 2. 实时编排（1:00–4:00）

对话区会依次出现：
- 画像师：JD 结构化、评分维度、受保护属性剥离；
- 探马：每份文件的 `format/chars`，重复文件标记；
- 批流动：第 1 批进入 → 解析 / 初筛 / 深评短名单 / 核查；
- 底部「实时生成」卡片：DeepSeek 的 token 流（原始 JSON token）。

讲解点：
- 扇出型工作（解析/初筛）走 `deepseek-chat`，判断/否决（画像/深评/核查）走 `deepseek-reasoner`；
- token 流与最终提交分离：schema 校验通过后才两阶段提交；前端看到的是"生成中"，不是最终结论；
- 工具轨迹可展开，里面每次调用都有 agent、时间、结果摘要。

## 3. HITL（4:00–5:30）

遇到 HITL 卡片时：
- 先读问题和推荐项；
- 点击一个选项，或在输入框写自定义回答后发送；
- 观察对话里出现"你的回答"，流水线继续。

讲解点：
- HITL 是真人决策，不是模型自问自答；回答写入 `decisions` 表，报告里可追溯；
- 如果服务重启，运行中的 HITL 会丢失，需要「续跑」重新触发。

## 4. 证据链（5:30–7:00）

运行完成后：
1. 最终消息展示 Top 候选人、分数、档位、核查否决率；
2. 点「查看证据链」或右侧「任务面板」；
3. 点任一候选人：
   - 解析字段 + 原文 quote + 字符区间；
   - 每轮评估（tier/phase、维度分数、理由）；
   - 核查逐条 verdict（supported/unsupported）与转人工原因；
   - 证据表。

讲解点：
- 模型只负责"引用哪句话 + 判断"，字符区间由平台计算；引用定位失败会被审计打回；
- 被核查打回的候选人会留下 `re_eval` 记录，最多 2 轮，仍不足转人工。

## 5. 合规与成本（7:00–8:00）

右侧「任务面板」：
- 合规：受保护属性剥离、重复投递、失败明细、HITL 决策记录；
- 成本：按 Agent/阶段的 token、缓存命中、USD 成本（来自 API usage；缺失时为估算）。

讲解点：
- 平台只给建议，不做自动录用/淘汰；
- flash/pro 分档的成本差异要在真实 Key 下实测，不用 mock 数字。

## 6. 报告与续跑（8:00–9:00）

- 顶栏「↓ Markdown」「↓ JSON」下载报告；
- 报告目录包含 `report.md`、`report.json`、`cost-report.md`、`convergence.svg`，**没有 report.html**；
- 如果演示中断，点「续跑」：不重新上传，从批次检查点继续；已 committed 的任务不会重跑。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 图片简历失败 | `pnpm ocr:download`，或设置 `BOLE_OCR_URL` |
| PDF 提示无文本层 | 扫描件导出为 PNG/JPG 再上传 |
| 没有 token 流 | 检查反向代理是否缓冲 SSE；本机直连应正常 |
| Key 无效/余额不足 | 页面设置处更新 Key；查看错误消息中的 DeepSeek 状态码 |
| HITL 卡住 | 服务重启会丢内存中的问题；「续跑」重新触发 |
| 想从空台账重来 | `pnpm bole reset --yes` |
