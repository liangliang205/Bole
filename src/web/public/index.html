使用帮助

  

    
    
    
    
    
  

  

    
从一份招聘需求开始

    
  1. 在「设置 → 模型」添加提供商、填写密钥，并选择模型。
  2. 新建会话，点击「＋」添加简历，输入岗位、技能与经验要求。
  3. 在附件按钮右侧选择默认或严格模式，点击发送箭头开始筛选。
  4. 遇到需要澄清的问题，在对话中选择选项或输入回答。
  5. 筛选完成后查看推荐与原文证据，继续追问或要求导出 Word / PDF。

    
支持 PDF、DOCX、图片、TXT、Markdown 和 HTML；单文件不超过 25MB。扫描 PDF 暂不支持，请转为图片上传。

    
结果用于辅助判断，最终招聘决定由人作出。

    
在右上角「任务面板 → 工作流」查看执行阶段、并行分支、核查修正轮次和审批子流程。发送按钮支持暂停与续跑，已完成的节点会从检查点复用。

  

  

    
名字背后的分工
多个角色分别处理需求、解析、评估与核查，便于追踪每一步的输入、结论和依据。

    

      
伯乐 · 主 Agent
协调筛选，规划批次、并发与深评策略；完成后回答追问并按需调用工具。

      
画像师 · 岗位定义
将招聘需求整理为 JD 和评分卡，澄清歧义，为候选人建立一致的评价标准。

      
探马 · 材料接入
读取文件、去重、提取正文或识别图片。这是确定性接入器，不是独立的 LLM 判断角色。

      
录事 · 简历解析
提取经历、技能等字段并关联原文引用，让后续评估有据可查。

      
相马官 · 匹配评估
按评分卡初筛，对短名单或异常项深评；收到核查反馈后修正结论。

      
监军 · 证据核查
检查结论与引用是否得到原文支持，并审查不当评分依据；可打回重评或转人工。

    
不同角色的核查可减少错误，但不能替代人工核实，也不意味着简历中的陈述已得到外部事实认证。

  

  

    
第一次配置：增加一位专职检查员

    
直接使用内置团队时，无需逐个配置角色。新增专项角色、替换某个环节或为不同项目保留组合时，才需要团队配置。“配置到团队”只是预选角色，保存团队后才会用于新会话。

    
  1. 打开「设置 → Agent 团队 → 创建与编辑」，选择「专职检查」职责。它会在解析后、评估前增加专项检查，不替换现有流程。
  2. 填写角色名称和工作指令。例如：
    检查候选人是否参与过支付或清结算项目。只列出有原文依据的经历；没有依据时不编造、不作淘汰决定。
    标识、版本、能力与输出契约会自动填写，通常不需要编辑 JSON。
  3. 选择快速或深入模型档位。需要业务资料时，勾选可参考的知识库角色；对应知识库也必须已启用并分配给该角色。
  4. 点击「发布并启用」。系统会保存、校验、注册版本并启用默认选择。若暂未完成，可先保存草稿。
  5. 在角色卡片点击「配置到团队」。保留基础分工，确认“增加专职检查”选择了新角色，再点「保存团队并用于新会话」。
  6. 关闭设置，新建会话。输入框底部会显示刚保存的团队，上传材料并开始筛选。

    
修改已有角色
在角色卡片点击「复制为新版本」，修改名称或工作指令后发布。使用“内置角色当前启用版本”的团队会在下一次新建会话时采用新版本；固定选择确切版本的团队，需要重新保存团队。已有会话继续使用原版本。

    
几个按钮有什么区别？
保存草稿
暂存编辑，不参与执行。
发布并启用
创建不可变版本，允许发现和默认选择；不会自动加入所有团队。
配置到团队
明确安排角色参与哪个环节；保存团队后才会用于新会话。
退役
停止新任务发现和选择该版本，已绑定的任务仍可继续执行。

    
实际执行中的工具操作按所选模式审批。知识库权限只决定可检索哪些参考资料，不授予工具或长期规则批准权。

  

  

    
功能在哪里

      
会话管理
左侧查看和搜索会话；会话菜单支持重命名、置顶、归档与删除。

      
任务面板
查看候选人、证据、合规与成本，了解推荐依据和失败明细。

      
知识库
从左下角进入，创建知识库并添加资料。在库内启停、选择适用 Agent，保存后仅这些角色自动检索；默认供相马官使用。

      
岗位与评分标准 · 记忆管理
从设置中的“岗位与评分标准”进入，创建岗位族，从已有会话或版本提出修订。审阅差异并批准后形成不可变新版本；新建会话可显式选择复用，旧任务仍按原快照执行。长对话采用带消息来源的提取式摘要，已确认条件直接读取台账。

      
模型与插件
在设置中管理模型提供商、档位与 MCP 插件。插件为完成后对话扩展工具能力。

      
Agent 团队
在“设置 → Agent 团队”管理角色定义、版本和团队。注册并激活后可按能力发现；团队可以替换已有角色或增加专职检查。任务创建后版本固定，退役不影响旧任务继续执行。实际运行调用模型并计费，工具操作受权限和审批模式约束。

      
文件与导出
完成后可以添加附件继续提问，明确要求时生成 Word / PDF；生成的文件可预览和下载。

      
主题
右上角切换日间与暗夜主题。

    

  

  

    
一个按钮控制运行
  • 发送箭头：开始筛选、提交回答或发送追问。
  • 暂停图标：筛选运行时点击，在当前批次或阶段边界暂停，保留已提交结果。
  • 等待图标：正在安全暂停，请等待当前任务收尾。
  • 播放图标：暂停或中断后点击，从检查点续跑；已提交结果会复用。

    
等待人工回答时，发送按钮优先提交回答。严格审批待处理时，请使用审批卡片，不会通过续跑绕过审批。

    
默认与严格模式
默认模式按现有流程执行，在疑点与终稿确认处请你介入。严格模式还要求批准筛选计划、每次工具调用和最终发布；解析、评分及预算内重评自动执行。

    
审批绑定具体内容并持久化，重启后仍可处理。拒绝即停止该操作。严格模式是授权控制，不是代码沙箱；执行中断的外部工具需要人工核对，系统不会自动重放。
